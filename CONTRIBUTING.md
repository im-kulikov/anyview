# Участие в разработке

- Работаем по этапам из `docs/SPEC.md` §11: один этап (или одна тема) — одна ветка — один PR в `main`. Работы после M6 оформляем как отдельные темы с понятным именем ветки (`fix/...`, `docs/...`, `feat/...`); баги и задачи — в GitHub Issues.
- Правила кода и зависимостей — `CLAUDE.md`. Перед добавлением пакета обоснуйте его в PR.
- Перед PR: `npm run lint && npm run typecheck && npm test -- --run && npm run build`. Описание PR — по шаблону `.github/pull_request_template.md`.
- Отступления от SPEC/макета и «не проверено» записываются в описание PR и, если они остаются в силе после мержа, в `docs/STATUS.md`.
- Значимые архитектурные решения — коротким ADR в `docs/adr/`.
- Новый каталог в `src/` — обновить дерево в `docs/SPEC.md` §3.
- Мерж только зелёного PR (squash). Прямых пушей в `main` нет.
- Компромисс в коде помечается комментарием `shortcut: <ограничение>, <когда переделать>`.
