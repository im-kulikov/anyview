# Журнал решений (ADR)

Формат записи: контекст — решение — последствия. Статус: **принято** (уже в коде) или **предложено** (записано до фазы 2, в коде не реализовано).

## Принято

### ADR-01. Единая лента для главной и `/anime`
Один ключ Query, `pageSize` 30, `refetchOnMount: false`, дедуп по `id`. Главная — один сетевой запрос, `/anime` уже в кэше. Живая лента даёт дубли между страницами, поэтому дедуп при склейке и в React-ключах. SPEC §5.1, §5.2.

### ADR-02. URL как состояние
`?episode=` и `?q=` меняются через `replace` + `preventScrollReset`; поле поиска живёт в `Layout` и не перемонтируется. Так «Назад» работает предсказуемо, а прокрутка не прыгает. SPEC §4, §5.6.

### ADR-03. Поиск и CORS-404
API отвечает 404 без CORS на пустой результат, браузер видит `TypeError`. Правило с `shortcut:`: базы не перебираем, пустой результат — если сеть онлайн и база уже отвечала. Устранение первопричины — прокси с CORS или свой сервер. API_CONTRACT §5.1.

### ADR-04. iOS: синхронный `play()` и фокус
Один `<video>` без `src` до первого нажатия, `preload="none"`, источники грузятся заранее; поиск в основном чанке, фокус — синхронно в касании. SPEC §5.5, §5.6.

### ADR-05. Поля ввода ≥ 16 px, зум не отключаем
Иначе iOS приближает страницу при фокусе. Правило повторено в SPEC §9, DESIGN §6 и CLAUDE.md намеренно; источник правды — SPEC §9.

### ADR-06. Хранение прогресса
Ключи `anyview:v1:*` (progress, history, favorites, recentSearches, prefs), одна запись истории на тайтл, порог «просмотрено» 90 %, снимок `TitleSummary`, лимиты 500/50/200/8. SPEC §7.

### ADR-07. Свой `IntersectionObserver` в `Cover`
Нативный `loading="lazy"` загружает картинки с запасом ≈ 1250 px и забивает канал; своя подгрузка в 200 px. SPEC §8.

### ADR-08. Прокручивается окно, а не контейнер
Нужно для `ScrollRestoration`. Приём макета с внутренним скроллом не переносим. SPEC §4, §5.

### ADR-09. GitHub Pages и копии `index.html` вместо hash-роутера
`404.html` даёт код 404 на `/title/*`, приложение при этом открывается. Критерий пересмотра — собственный домен или хостинг с SPA-fallback и заголовками (CSP). SPEC §10.

## Предложено (до фазы 2)

- **ADR-10. Идентификаторы и миграция данных.** `av-*` персистятся без namespace; при смене провайдера данные пользователя осиротеют. Нужны правила legacy-id, `externalIds`, миграция `localStorage`.
- **ADR-11. Выбор провайдера и включение типов.** `VITE_PROVIDER` → фабрика; `catalog()` как единственный источник «что включено»; `comingSoon` как декоратор. Сейчас провайдер собран вручную в `src/api/index.ts`.
- **ADR-12. Владелец кэша.** TanStack Query — единственный кэш; в адаптере только дедуп in-flight; TTL по типам данных; политика ретраев (не ретраить 4xx/429).
- **ADR-13. Архитектура плеера.** Редьюсер состояния, движки по `Stream.kind` (hls/dash/iframe), выбор источника по озвучке/студии/высоте, `expiresAt`.
- **ADR-14. Модель серий для сериалов.** `(season, number)` как ключ порядка, `absoluteNumber` для аниме, стабильность `Episode.id`.
- **ADR-15. Безопасность на статическом хостинге.** CSP через `<meta>`, самохостинг шрифтов, строгий `https()`, критерий ухода с GitHub Pages.
- **ADR-16. Наблюдаемость.** `report()` + приёмник ошибок; что считать инцидентом (рост `parse`-ошибок, 5xx).
- **ADR-17. Хранилище: схема и версионирование.** Формат `{v, data}`, миграции, валидация элементов, атомарность progress/history.
