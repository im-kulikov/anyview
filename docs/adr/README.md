# Журнал решений (ADR)

Формат записи: контекст — решение — последствия. Статус: **принято** (уже в коде) или **предложено** (записано до фазы 2, в коде не реализовано).

## Принято

### ADR-01. Единая лента для главной и `/anime`
Один ключ Query, `pageSize` 30, `refetchOnMount: false`, дедуп по `id`. Главная — один сетевой запрос, `/anime` уже в кэше. Живая лента даёт дубли между страницами, поэтому дедуп при склейке и в React-ключах. SPEC §5.1, §5.2.

### ADR-02. URL как состояние
`?episode=` и `?q=` меняются через `replace` + `preventScrollReset`; поле поиска живёт в `Layout` и не перемонтируется. Так «Назад» работает предсказуемо, а прокрутка не прыгает. SPEC §4, §5.6.

### ADR-03. Поиск и CORS-404
API отвечает 404 без CORS на пустой результат, браузер видит `TypeError`. Правило с `shortcut:`: базы не перебираем, пустой результат — если сеть онлайн и база уже отвечала. Устранение первопричины — прокси с CORS или свой сервер. API_CONTRACT §5.1.

### ADR-04. iOS: синхронный `play()` и фокус
Один `<video>` без `src` до первого нажатия, `preload="none"`, источники грузятся заранее; поиск в основном чанке, фокус — синхронно в касании. SPEC §5.5, §5.6.

### ADR-05. Поля ввода ≥ 16 px, зум не отключаем
Иначе iOS приближает страницу при фокусе. Правило повторено в SPEC §9, DESIGN §6 и CLAUDE.md намеренно; источник правды — SPEC §9.

### ADR-06. Хранение прогресса
Ключи `anyview:v1:*` (progress, history, favorites, recentSearches, prefs), одна запись истории на тайтл, порог «просмотрено» 90 %, снимок `TitleSummary`, лимиты 500/50/200/8. SPEC §7.

### ADR-07. Свой `IntersectionObserver` в `Cover`
Нативный `loading="lazy"` загружает картинки с запасом ≈ 1250 px и забивает канал; своя подгрузка в 200 px. SPEC §8.

### ADR-08. Прокручивается окно, а не контейнер
Нужно для `ScrollRestoration`. Приём макета с внутренним скроллом не переносим. SPEC §4, §5.

### ADR-09. GitHub Pages и копии `index.html` вместо hash-роутера
`404.html` даёт код 404 на `/title/*`, приложение при этом открывается. Критерий пересмотра — собственный домен или хостинг с SPA-fallback и заголовками (CSP). SPEC §10.

### ADR-18. Подсказки загрузки генерируются при сборке
`preconnect` и `preload` первой страницы ленты были записаны в `index.html` с жёстким хостом и `quantity=30`: при смене `VITE_ANIMEVOST_BASES`, `FEED_PAGE_SIZE` или `VITE_PROVIDER` preload превращался в лишний запрос (≈ 106 КБ) на чужой домен. Теперь `config/htmlPlugin.ts` (Vite `transformIndexHtml`, без зависимостей) строит их из тех же `parseBases`/`lastPath`/`FEED_PAGE_SIZE`, которыми пользуется адаптер; `og:image` получает абсолютный адрес из `VITE_SITE_URL`. Последствия: `index.html` не содержит адресов API; тест `config/htmlPlugin.test.ts` держит их согласованными. Закрывает CODE-26, ARCH-19.

### ADR-19. Шрифт Exo 2 с собственного хоста
Google Fonts давали внешний CSS, два preconnect, inline `onload` (мешал строгому CSP) и единую точку отказа (доступность из РФ). Три подмножества переменного woff2 (cyrillic 19 КБ, latin 41 КБ, latin-ext 31 КБ; скачивается только нужное по `unicode-range`) лежат в `public/fonts`, `@font-face` — в `styles/fonts.css`. Лицензия шрифта — SIL OFL, раздача разрешена. Lighthouse не изменился (74–76 до и после): выигрыш в устойчивости и возможности CSP. Preload шрифта не делаем: он конкурирует за канал с JS и лентой до первой отрисовки.

### ADR-20. CSP через `<meta>`
Только в сборке (dev-сервер Vite использует inline-скрипты). `default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'` (inline нужен атрибутам `style`, например `aspect-ratio` в `Cover`), `img-src 'self' https: data:`, `media-src https: blob:` (видео и картинки приходят с нескольких CDN animevost, список хостов заранее неизвестен), `font-src 'self'`, `connect-src 'self'` + origin баз API (из `VITE_ANIMEVOST_BASES`, при `VITE_PROVIDER=anyview` — из `VITE_API_BASE`), `object-src 'none'`, `base-uri 'self'`, `form-action 'none'`. `frame-ancestors` и report-only через `<meta>` не работают; при уходе с GitHub Pages перенести CSP в заголовки. Проверено в браузере: картинки, шрифты, запросы к API и загрузка mp4 проходят, нарушений нет. Закрывает ARCH-18 (CSP).

### ADR-21. Снимок ленты для повторного визита (stale-while-revalidate)
Холодный старт: HTML → JS → `/last` (106 КБ, ≈ 1.3 с) → обложка. Для вернувшегося пользователя первая страница ленты (≈ 13 КБ после маппинга) хранится в `anyview:v1:feed`, при старте кладётся в кэш Query как устаревшая (`updatedAt: 0`), запрос к API идёт как раньше и заменяет данные; ошибка сети оставляет снимок на экране. Безопасность: элементы проходят ту же проверку формы, что и остальное хранилище, возраст ≤ 7 суток, «вечно» показанных старых данных нет (каждая загрузка начинается с перепроверки). «Главная — один сетевой запрос» сохраняется. **Отклонено**: снимок ленты, вшитый в сборку (cron-деплой + предзагруженная обложка в HTML). Прототип дал Lighthouse 79–83 вместо 75 (только вместе с отложенной загрузкой остальных обложек), но показывает всем новым посетителям устаревшую ленту, делает сборку зависимой от чужого API и множит деплои. Пересмотреть при отсутствии прокси/своего сервера (фаза 2).

### ADR-22. Отмена общих запросов по числу подписчиков
`title`, `episodes`, `sources` разделяют один `/info` и один `/playlist` на тайтл, поэтому отмена сигнала одной страницы не могла оборвать запрос (и не обрывала: `fetch` шёл без сигнала, SPEC §6 нарушался). Теперь у общей загрузки свой `AbortController` и счётчик подписчиков (`memo` в `providers/animevost/index.ts`): `abort()` — когда отписался последний; недогруженная запись удаляется из кэша, завершённая остаётся (поздняя отмена кэш не стирает). Тесты в `provider.test.ts`. Закрывает CODE-17.

### ADR-23. Поиск: контрольный запрос вместо эвристики «база уже отвечала»
Браузер не отличает 404 без CORS («ничего не нашли») от обрыва сети. Прежнее правило давало ложную ошибку на холодном старте `/search?q=…` (CODE-21). Теперь при `TypeError` идёт один запрос `/last?page=1&quantity=1`: ответил — значит, пусто. Остаётся `shortcut:` до прокси с CORS или своего сервера. Альтернатива «ждать префетч ленты» отвергнута: связывает поиск с лентой и ломается при её сбое. API_CONTRACT §5.1. Закрывает CODE-21, ARCH-10 (в части различения; перебор баз для поиска не добавлен: поиск — POST, повтор на второй базе удвоил бы нагрузку при каждом пустом запросе).

### ADR-24. Строгий `https()`
`https(url, base?)` возвращает `undefined` для любых схем кроме `http`/`https` и нечитаемых адресов, разрешает относительные адреса от `base`. Список разрешённых хостов не вводим: CDN animevost меняются, ложный отказ ломает картинки и видео, а защиту от чужих хостов даёт CSP (ADR-20). Закрывает CODE-24, ARCH-18 (https).

### ADR-25. Освежение ленты и отчёты об ошибках
Лента не менялась до перезагрузки вкладки (CODE-35). Полный refetch бесконечного запроса перезагрузит все страницы (до ≈ 12 МБ) и нарушит «возврат на `/anime` не перезагружает загруженные страницы», поэтому при возврате на вкладку с данными старше 15 мин (`3 × staleTime`) запрашивается только первая страница и подставляется на место первой (`api/refresh.ts`). Дубли на стыке убирает `dedupe`. Навигация по-прежнему без запросов. Рядом: `lib/report.ts` и перехватчики (`app/diagnostics.ts`) — первый шаг ADR-16 без приёмника; `vite:preloadError` перезагружает страницу один раз за минуту (ARCH-17). Закрывает CODE-35, ARCH-12 (освежение, `select` вынесен из рендера), ARCH-17.

### ADR-26. Версия схемы хранилища и вытеснение при квоте
Ключи остаются `anyview:v1:*`, формат не менялся. Добавлены общий ключ `anyview:schema` и `migrate()` с таблицей `MIGRATIONS` (шаг n → n+1), чтобы смена формата не требовала нового префикса и не бросала данные: сначала миграция, потом чтение. Правила: нет записи = v1; упавшая миграция не повышает версию (чтение защищено поэлементной валидацией); версия выше известной не понижается. При `QuotaExceededError` вытесняется только кэш (`anyview:v1:feed`), пользовательские ключи не трогаем; не помогло — режим памяти (CODE-06). Атомарность progress/history и обновление снимков избранного (ARCH-23) не делались: потеря между двумя `set` и устаревший снимок не ломают экраны. Закрывает ARCH-04 (миграции), ARCH-05 (квота).

### ADR-27. Синхронизация: модель данных и слияние
Что синхронизируется: прогресс, история, избранное. **prefs (качество, громкость, автопереход) и недавние запросы — нет**: они зависят от устройства (громкость на телефоне и компьютере разная), а их потеря ничего не стоит. Состояние (`LocalData` в `lib/storage.ts`) сливается чистой функцией `mergeData` (`src/sync/merge.ts`), без DOM и сети:
- **progress** — по `episodeId` побеждает больший `updatedAt`; лимит 500 (вытесняются старые).
- **history** — одна запись на тайтл, самая свежая; лимит 50. Затем сверка с прогрессом: запись старше досмотренной (≥ 90 %) позже серии того же тайтла устарела и отбрасывается. Так правило «досмотрено → следующая серия или удаление» переживает слияние: устройство, где досмотрели, уже создало запись на следующей серии (она свежее) либо удалило свою, и старая копия с другого устройства не воскресает.
- **favorites** — `TitleSummary[]` не хранит времени, поэтому рядом лежит `anyview:v1:favoritesMeta`: `{[id]: {at, del?}}`, где `at` — момент добавления или удаления, `del` — «надгробие». Побеждает более позднее действие, при равенстве удаление сильнее (удалённое не воскресает). Лимиты: 200 живых, 300 «надгробий» (самые свежие). Порядок — по `at`, новые сверху.
- Ключи `anyview:v1:*` остаются, формат существующих не менялся. Схема 1 → 2 (`MIGRATIONS[1]`): уже добавленным тайтлам выставляются метки `at` = 1, 2, … (старые, порядок сохраняется). Без метки (откат деплоя и повторный вход) избранное считается добавленным с `at` = 0.
- Равные `updatedAt` разрешаются сравнением канонического JSON (ключи отсортированы), а не порядком аргументов. Свойства, проверенные тестами на 300 случайных состояний: **коммутативность** и **идемпотентность** (в том числе `merge(a, merge(a, b)) = merge(a, b)`), слияние с пустым не теряет данных. **Ассоциативности нет**: отбрасывание устаревшей записи истории необратимо, и порядок трёх слияний может дать разный результат в редком случае «досмотрел, затем сбросил и пересмотрел»; сходимость обеспечивается идемпотентностью (каждое устройство каждый раз сливает облако с локальным).
- Часы устройств считаются примерно верными (метки — `Date.now()`): расхождение в минуты проигрывает только в пределах этих минут, расхождение в дни может отдать победу не тому устройству. Принято, серверное время в метках не используем (нужен был бы второй документ и лишние запросы).
- `resetProgress` («С начала») теперь обновляет `updatedAt`: иначе сброс проигрывал бы старой записи другого устройства.
- **Атомарность (ARCH-23)**: `batch()` откладывает уведомления подписчиков до конца группы записей; `saveProgress`, `resetProgress`, `toggleFavorite` и применение слитого состояния (`writeLocal`) меняют связанные хранилища одним согласованным обновлением для `useSyncExternalStore`. Запись в `localStorage` по-прежнему идёт по ключам по очереди (транзакций у него нет), но экраны промежуточного состояния не видят. Закрывает ARCH-23 в части progress/history/избранного; обновление снимков избранного при открытии тайтла по-прежнему не делается.
- **Размер**: правила Firestore требуют `data.size() < 200000`. Для облака состояние обрезается (`fitForCloud`) до 190 000 байт UTF-8: пачками по десятой части выбрасываются самые старые записи прогресса и истории, если их нет — «надгробия», затем избранное. Локальные данные не обрезаются; тест на 200 длинных избранных и 500 серий.

## Предложено (до фазы 2)

- **ADR-10. Идентификаторы и миграция данных.** `av-*` персистятся без namespace; при смене провайдера данные пользователя осиротеют. Нужны правила legacy-id, `externalIds`, миграция `localStorage`.
- **ADR-11. Выбор провайдера и включение типов.** `VITE_PROVIDER` → фабрика; `catalog()` как единственный источник «что включено»; `comingSoon` как декоратор. Сейчас провайдер собран вручную в `src/api/index.ts`.
- **ADR-12. Владелец кэша.** TanStack Query — единственный кэш; в адаптере только дедуп in-flight; TTL по типам данных. Политика ретраев (не ретраить 4xx) и TTL адаптера уже сделаны; кэш сырых элементов в адаптере остаётся.
- **ADR-13. Архитектура плеера.** Редьюсер состояния, движки по `Stream.kind` (hls/dash/iframe), выбор источника по озвучке/студии/высоте, `expiresAt`.
- **ADR-14. Модель серий для сериалов.** `(season, number)` как ключ порядка, `absoluteNumber` для аниме, стабильность `Episode.id`.
- **ADR-15. Безопасность на статическом хостинге.** CSP через `<meta>` и самохостинг шрифтов сделаны (ADR-19, ADR-20); осталось: строгий `https()`, критерий ухода с GitHub Pages.
- **ADR-16. Наблюдаемость.** `report()` и перехватчики есть (ADR-25); осталось: приёмник ошибок и что считать инцидентом (рост `parse`-ошибок, 5xx).
- **ADR-17. Хранилище: остаток.** Версии, миграции, валидация элементов и квота сделаны (ADR-26); атомарность progress/history сделана (ADR-27); осталось: обновление снимков избранного при открытии тайтла, ключи с namespace провайдера (ARCH-01: сервер принимает legacy `av-*`, API_CONTRACT).
