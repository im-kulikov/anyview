# ТЗ: anyview — сайт для просмотра аниме, сериалов и фильмов

**Версия:** 1.1 (MVP) · **Дата:** 09.10.2026 · **Исполнитель:** Claude Code (cloud)

Связанные документы: [DESIGN.md](DESIGN.md) — дизайн и макеты, [API_CONTRACT.md](API_CONTRACT.md) — контракт данных и адаптер, [RESEARCH.md](RESEARCH.md) — источники и фаза 2, [ASSETS.md](ASSETS.md) — логотип и графика.

---

## 0. Кратко

Делаем быстрый современный сайт (SPA) для просмотра аниме. Сериалы и фильмы пока показывают красивую заглушку. Своего сервера нет: данные и видео берём из публичного API animevost через адаптер, который приводит их к нашему единому контракту. Позже контракт будет отдавать свой сервер, и фронтенд переключится без переписывания экранов.

**Входит в MVP:**
- главная: новые серии, продолжить просмотр, последние тайтлы;
- раздел «Аниме»: сетка последних обновлений с бесконечной прокруткой;
- разделы «Сериалы» и «Фильмы»: заглушка «в разработке»;
- поиск по аниме, доступный со всех экранов;
- страница тайтла: постер, фон, названия, характеристики, описание, теги, плеер с плейлистом серий;
- прогресс просмотра, «продолжить просмотр», избранное и недавние запросы в `localStorage`;
- mobile-first вёрстка + десктоп;
- автодеплой в GitHub Pages из `main`.

**Не входит:** аккаунты, свой сервер, торренты, фильтры по жанру/году (у animevost нет таких методов), комментарии, уведомления, SSR/SEO, светлая тема, офлайн-режим.

---

## 1. Принципы

1. **Mobile-first.** Сначала 360–430 px, потом планшет и десктоп.
2. **Скорость важнее эффектов.** UI не фризит: никаких тяжёлых UI-китов, всё лишнее — ленивыми чанками, картинки ленивые, место под них зарезервировано.
3. **Экраны не знают об animevost.** Компоненты работают только с типами из `API_CONTRACT.md`. Всё, что связано с animevost, живёт в `src/api/providers/animevost/`.
4. **Минимум зависимостей.** Новая библиотека — только если без неё заметно больше кода.
5. **Дизайн = макет.** Порядок приоритетов — DESIGN.md §0.

## 4. Маршруты

| Путь | Экран | Макет (моб. / десктоп) |
|---|---|---|
| `/` | Главная | `Main` / `Desktop` |
| `/anime` | Аниме: последние обновления | `Catalog` / `DesktopAnime` |
| `/series` | Заглушка «Сериалы» | `Soon` (section=series) / `DesktopSoon` |
| `/movies` | Заглушка «Фильмы» | `Soon` (section=movies) / `DesktopSoon` |
| `/title/:id` | Тайтл; `?episode=<episodeId>` открывает нужную серию | `Title` / `DesktopTitle` |
| `/search?q=` | Поиск | `Search` / `DesktopSearch` |
| `*` | 404: «Такой страницы нет» + «На главную», «Аниме» | — |

- `id` непрозрачный (в MVP `av-4020`).
- Страница тайтла с плеером — ленивый чанк (`lazy`). Поиск — **в основном чанке**: на iOS клавиатура открывается, только если фокус ставится синхронно в обработчике касания (§5.6).
- `<ScrollRestoration />` возвращает позицию прокрутки при «Назад». Поэтому прокручивается **окно**, а не внутренний контейнер (§5, общий каркас).
- Смена query-параметров без смены экрана (`?episode=`, `?q=`) — через `setSearchParams(…, { replace: true, preventScrollReset: true })`, иначе роутер прокрутит страницу наверх.
- `document.title` на каждой странице: «Название — anyview».

## 5. Экраны и поведение

### Общий каркас

- **Мобильный (< 1024 px).** Прокручивается окно. Шапка — `position: sticky; top: 0` (лого + поле поиска). Нижняя панель разделов (Главная, Аниме, Сериалы, Фильмы) — `position: fixed; bottom: 0` с `padding-bottom: calc(8px + env(safe-area-inset-bottom))`; у `body` нижний отступ на высоту панели. В `<meta name="viewport">` добавить `viewport-fit=cover`. На экране поиска (`/search`) шапка переключается в режим поиска, а нижняя панель скрыта (как в макете `Search`).
  > В макетах мобильные экраны сделаны с внутренним скролл-контейнером — это приём макета, в коде так не делать.
- **Десктоп (≥ 1024 px).** Шапка `position: sticky`, полупрозрачная с `backdrop-filter: blur(14px)`: лого, разделы-«таблетки», поле поиска справа (подсказка `/`). Нижней панели нет. Контейнер max 1280 px. Сериалы и Фильмы помечены «скоро».
- **Горизонтальные ленты на десктопе** (`pointer: fine`): кнопки «‹ ›» по краям ленты появляются при наведении и прокручивают на ширину видимой части; полоса прокрутки скрыта. На тач-устройствах — свайп и `scroll-snap`.

### 5.1 Главная `/`

Один сетевой запрос: та же бесконечная лента, что на `/anime` (тот же ключ Query, `pageSize` 30), — первая страница. Если пользователь потом откроет `/anime`, данные уже в кэше.

Секции сверху вниз:

1. **Новые серии** — лента. Тайтлы со `status = ongoing` и `latestEpisode` из первой страницы, до 12. На обложке бейдж «N серия». Кнопка-стрелка → `/anime`.
2. **Продолжить просмотр** — из `localStorage` (§7), до 10, свежие первыми. Телефон — лента карточек 16:9; десктоп — сетка `auto-fill, minmax(280px, 1fr)`, как в макете. Карточка: кадр серии, полоса прогресса, «6 серия · осталось 12 мин». Клик → `/title/:id?episode=…`. Нет истории — секции нет.
3. **Избранное** — лента обычных карточек, только если есть избранное (в макете нет, тот же компонент).
4. **Последние тайтлы** — сетка из 12 следующих тайтлов первой страницы, **не попавших** в «Новые серии». Кнопка «Показать ещё» / «Весь каталог» → `/anime`.
5. **Баннер «Сериалы и фильмы скоро»** → `/series`.

### 5.2 Аниме `/anime`

- Заголовок «Аниме», подзаголовок «Последние обновления · {total} тайтлов» (`Intl.NumberFormat('ru')`, склонение через `Intl.PluralRules`).
- Сетка карточек: 3 колонки на телефоне (2 при ширине < 360 px), шире — по DESIGN.md §2.
- Бесконечная прокрутка: `useInfiniteQuery`, 30 на страницу, подгрузка за 600 px до конца (`IntersectionObserver`). Лента живая (сортировка по времени обновления), поэтому между страницами бывают дубли: **убирать дубли по `id`** при склейке страниц (и в React-ключах).
- `refetchOnMount: false` для этой ленты: возврат на страницу не перезагружает все загруженные страницы.
- Пока грузится — ряд скелетонов того же размера. Ошибка подгрузки — строка «Не удалось загрузить» + «Повторить», загруженное не пропадает.
- Возврат с тайтла — та же позиция прокрутки (кэш Query + `ScrollRestoration`).

### 5.3 Карточка тайтла (общая)

- Обложка 2:3 (`aspect-ratio`), `object-fit: cover` — любые размеры исходника без пустот и искажений. Пока картинка грузится — фон-заглушка, затем появление (opacity 150 мс). Ошибка картинки — заглушка с первой буквой названия.
- Рейтинг — тёмная «таблетка» со звездой в правом нижнем углу обложки; нет рейтинга — нет таблетки.
- Бейдж «N серия» (акцентный) — в левом верхнем углу, только если есть `latestEpisode` и карточка в ленте обновлений.
- Под обложкой: «Тип · Год» (короткие подписи из DESIGN.md §5), название в 2 строки с многоточием.
- Вся карточка — одна ссылка `<a>`. На десктопе при наведении обложка увеличивается (1.04), с учётом `prefers-reduced-motion`.
- Префетч: только на десктопе (`matchMedia('(pointer: fine)')`) по наведению — `episodes(titleId)`. Тайтл отдельно не префетчим: адаптер отдаёт его из уже загруженного элемента ленты (API_CONTRACT.md §5.3).

### 5.4 Тайтл `/title/:id`

Запросы `title(id)` и `episodes(id)` идут параллельно, сразу после этого — `sources()` для открываемой серии и следующей (нужно плееру, §5.5). Пока грузится — скелетон в форме страницы.

**Какая серия открывается** (одна функция `pickEpisode`, ею пользуются и плеер, и кнопка):
1. `?episode=` из URL, если такая серия есть и доступна;
2. иначе серия этого тайтла, начатая и не досмотренная (< 90 %), самая свежая по времени;
3. иначе первая доступная серия после последней просмотренной (≥ 90 %);
4. иначе первая доступная серия.

Блоки (порядок как в макете):

1. **Шапка-герой.** Фон: `backdrop`, если есть, иначе тот же постер; в обоих случаях размыт (`filter: blur`), затемнён к цвету фона. Постер 2:3 (моб. 200 px по центру, десктоп 260 px слева). Строка «Тип · Год · Статус» (длинные подписи DESIGN.md §5), название RU (h1), оригинальное название, рейтинг + голоса + возрастной рейтинг (если есть).
2. **Кнопки.** Основная: «▶ Смотреть N серию» для `pickEpisode`; «▶ Продолжить N серию», если у неё есть сохранённая позиция; «▶ Смотреть», если у серии нет номера (фильм, OVA). Нажатие прокручивает к плееру и запускает воспроизведение (§5.5). «В избранное» — переключатель, хранится локально.
3. **Характеристики** (`<dl>`): Тип, Эпизоды, Год, Статус, Режиссёр, Озвучка (тексты — DESIGN.md §5). Пустые поля не показываем; у фильма нет строки «Эпизоды».
4. **Описание** — 4 строки на телефоне, 3 на десктопе, «Читать полностью» / «Свернуть» (только если текст не влез). Только плоский текст, никакого `dangerouslySetInnerHTML`.
5. **Теги** — жанры «таблетками» `#Жанр`. В MVP некликабельные: фильтра по жанру в API нет.
6. **Плеер** (§5.5).
7. **Серии (плейлист).** Моб. — список под плеером. Десктоп — колонка справа от плеера со своей прокруткой (max-height ≈ высоте плеера). Строка: кадр 16:9 (кадр серии или заглушка), «N серия», подпись, полоса прогресса, галочка у просмотренных. Подпись: «Просмотрено» (≥ 90 %), «Осталось X мин» (есть позиция и длительность), «Новая» (это `latestEpisode` онгоинга и прогресса нет), иначе пусто. Текущая серия — рамка акцентного цвета и значок «играет». Ещё не вышедшая (`available: false`) — пунктир, часики, «Выйдет 16 октября» (или «Скоро», если даты нет), не кликается.

Десктоп дополнительно: хлебные крошки «Аниме › Название».

Тайтл не найден (`ApiError('not_found')`) — экран 404 с «Перейти в аниме».

### 5.5 Плеер

**Запуск (критично для iPhone).** iOS Safari разрешает `play()` со звуком только синхронно в обработчике касания. Поэтому:
- На странице один `<video playsInline>` на всё время (без `key` на серию). До первого нажатия у него только `poster` (кадр серии), **без `src`** — видео не грузится.
- Источники текущей и следующей серии загружены заранее (§5.4), так что в обработчике нажатия («Играть», кнопка «Смотреть N серию», клик по серии в плейлисте) мы синхронно ставим `src`, при необходимости `currentTime`, и вызываем `play()` — без `await` до вызова.
- Если `play()` отклонён — показываем большую кнопку «Играть» поверх кадра.
- Переход из «Продолжить просмотр» открывает серию на сохранённой позиции и показывает «Продолжаем с 08:14 · С начала», но запускает воспроизведение только по нажатию.

**Контролы** поверх видео: играть/пауза, следующая серия, громкость (десктоп), прогресс с буфером и перемоткой (тач и мышь), время «08:14 / 23:40», метка качества, «картинка в картинке» (только если `document.pictureInPictureEnabled`), полный экран. Контролы прячутся через 3 с без активности во время воспроизведения. Визуальный размер кнопок — по макету, зона нажатия ≥ 44 px (§9).

**Качество** SD 480p / HD 720p — переключатель под плеером, выбор по `Source.quality.height`. Смена качества сохраняет позицию и состояние «играет/пауза». По умолчанию (`prefs.quality = 'auto'`): SD, если `navigator.connection?.saveData` или `effectiveType` ∈ `slow-2g / 2g / 3g`; иначе HD. В Safari и Firefox `navigator.connection` нет — там HD. Ручной выбор запоминается.

**Плейлист:** клик по серии → смена источника и `?episode=` (`replace`, `preventScrollReset`), запуск синхронно в обработчике. «Предыдущая» / «Следующая» — кнопки под плеером.

**Автопереход:** по окончании серии — оверлей «Следующая серия через 5…» с «Отмена»; настройка вкл/выкл. В нативном полноэкранном режиме iOS наши оверлеи не видны — там переход на следующую серию сразу, без отсчёта.

**Прогресс:** позиция сохраняется каждые 5 с, на паузе и при `visibilitychange`. Просмотренной считается серия, досмотренная до ≥ 90 %.

**Клавиатура (десктоп):** Пробел/K — пауза, ←/→ — ±10 с, ↑/↓ — громкость, F — полный экран, M — звук, Shift+N — следующая серия. Хоткеи не срабатывают, когда фокус в поле ввода.

**Media Session API:** название, серия, обложка, кнопки «следующая/предыдущая» на экране блокировки.

**Ошибка видео:** пробуем другое качество; не помогло — «Не удалось загрузить видео» + «Повторить».

**iOS (iPhone):** полноэкранный режим — нативный (`webkitEnterFullscreen`), со своими контролами Safari. Проверено на iPhone (iOS 18.7, Safari 27, 09.10.2026): `requestFullscreen` у `div` и у `video` отсутствует, поэтому показать свои кнопки поверх видео в полном экране нельзя; **известное ограничение:** из нативного полного экрана серию переключить нельзя (работает только автопереход по окончании, без отсчёта). Псевдополноэкранный режим (`position: fixed`) рассматривали и отложили (docs/REVIEW.md, UX-IOS-01). Поэтому выбор серии — из самого плеера в инлайн-режиме: «Предыдущая», «Следующая» и «Список серий» (панель внутри контейнера плеера; выбор серии запускает воспроизведение синхронно в обработчике касания). На iPad и десктопе работает Fullscreen API контейнера — панель серий видна и в полном экране.

### 5.6 Поиск `/search?q=`

- **Поле поиска — настоящий `<input>` в шапке на всех экранах** (компонент живёт в `Layout` и не перемонтируется при переходе).
  - Телефон: фокус в поле (касание) → переход на `/search`, шапка в режиме поиска (кнопка «Назад» + поле, без лого), нижняя панель скрыта. Поскольку это тот же `<input>`, фокус и клавиатура iOS сохраняются.
  - Десктоп: ввод в поле шапки → первый раз `navigate('/search?q=…')` (запись в историю, чтобы «Назад» вернул на предыдущий экран), дальше — `replace` + `preventScrollReset`. `/` фокусирует поле.
- Поиск от 2 символов, задержка 300 мс, прошлый запрос отменяется (`AbortSignal`), результаты кэшируются. Повторов нет (`retry: 0`): про пустой ответ animevost — API_CONTRACT.md §5.1.
- Область поиска: «Аниме» (активно), «Сериалы · скоро», «Фильмы · скоро» (неактивны).
- Пустой запрос: недавние запросы (до 8, тап подставляет) + «Часто ищут» (первые тайтлы ленты обновлений из кэша).
- Результаты: телефон — список (обложка 2:3, RU, оригинальное, «Тип · Год · ★»), десктоп — сетка карточек. Заголовок «Результаты по запросу «…»», «Найдено: N» (при 50 — «Найдено: 50+», animevost больше не отдаёт).
- Ничего не нашли — «Ничего не нашли. Попробуйте оригинальное название или часть слова».
- Запрос попадает в «недавние», когда из результатов открыли тайтл.

### 5.7 Заглушка `/series`, `/movies`

По макету `Soon`: иллюстрация из веером разложенных пустых карточек с иконкой раздела и плашкой «В РАЗРАБОТКЕ», заголовок «Сериалы уже в пути» / «Фильмы уже в пути», текст, три пункта «что будет», кнопки «Смотреть аниме» и «На главную». Активный пункт навигации — соответствующий раздел. Тексты — в макете.

## 6. Загрузка данных

- `QueryClient` по умолчанию: `staleTime` 5 мин для лент и поиска, 60 мин для тайтла и серий; `gcTime` 2 ч (больше `staleTime`, иначе 60 мин не работают); `retry: 2` с экспоненциальной паузой, но не для `ApiError` вида `not_found` и `parse`; `refetchOnWindowFocus: false`.
- Все запросы принимают `AbortSignal` (уход со страницы отменяет запрос).
- Ошибки — только `ApiError` (API_CONTRACT.md §2). Экран показывает `ErrorState` с «Повторить»; ошибка в одной секции главной не ломает остальные.
- Нет сети (`navigator.onLine === false`) — тонкая плашка «Нет подключения к интернету» над нижней панелью.
- Глобальный `ErrorBoundary` на уровне маршрута: «Что-то пошло не так» + «Обновить».

## 7. Локальные данные

Один модуль `lib/storage.ts`: ключи с версией, чтение в `try/catch`, битые данные сбрасываются, лимиты по размеру.

| Ключ | Содержимое | Лимит |
|---|---|---|
| `anyview:v1:progress` | `{[episodeId]: {titleId, position, duration, updatedAt}}` | 500 записей, вытесняются старые |
| `anyview:v1:history` | `[{title: TitleSummary, episodeId, episodeName, still?: string, position, duration, updatedAt}]` — **одна запись на тайтл**, обновляется на месте и поднимается наверх | 50 |
| `anyview:v1:favorites` | `TitleSummary[]` | 200 |
| `anyview:v1:recentSearches` | `string[]` | 8 |
| `anyview:v1:prefs` | `{quality: 'auto'\|'sd'\|'hd', autoNext: boolean, volume: number, muted: boolean}` | — |

Правила «Продолжить просмотр»: когда серия досмотрена до ≥ 90 %, запись тайтла переходит на следующую доступную серию (позиция 0); следующей нет — запись удаляется. Снимок `TitleSummary` хранится целиком, чтобы «Продолжить просмотр» и «Избранное» рисовались без сети.

## 8. Производительность

Что известно заранее: API animevost не сжимает ответы (страница из 30 тайтлов ≈ 105 КБ), постеры приходят одного размера (≈ 400 × 565, 155–180 КБ JPEG) со стороннего домена. Поэтому:

- `<link rel="preconnect">` к `api.animetop.info`, `static.openni.ru` и Google Fonts.
- Загрузка первой страницы ленты стартует в `main.tsx` до первого рендера (`queryClient.prefetchInfiniteQuery`).
- `fetchpriority="high"` + `loading="eager"` — только у 1–2 первых видимых обложек и постера тайтла; остальные `loading="lazy"`, `decoding="async"`.
- Под каждую картинку зарезервировано место (`aspect-ratio`).
- Тайтл с плеером — отдельный чанк; стартовый JS ≤ 150 КБ gzip.
- Шрифт: только нужные начертания (400, 500, 600, 700, 800), `display=swap`.
- Анимации — только `transform`/`opacity`. Скелетоны замирают при `prefers-reduced-motion`.
- Нет CSS-in-JS-рантайма и UI-китов. Виртуализацию и `content-visibility` не добавлять, пока профилировщик не покажет проблему.

Цели (Lighthouse mobile на задеплоенном сайте, `/` и `/anime`): Performance ≥ 90, LCP ≤ 2.5 с, CLS ≤ 0.05, INP ≤ 200 мс. Первый замер — в конце M3. Если 90 недостижимо из-за чужого API и картинок, допустимо ≥ 80 с объяснением в PR, что именно упирается (без ухудшения CLS и INP).

## 9. Доступность

- Контраст текста ≥ 4.5:1 (крупный ≥ 3:1). В макете это соблюдено: на акцентном фоне — белый текст, активный пункт навигации — белая подпись.
- Всё интерактивное — настоящие `<a>` / `<button>` / `<input>`; иконочные кнопки с `aria-label`; видимый фокус (`:focus-visible`, белая обводка 2 px).
- **Зона нажатия ≥ 44 × 44 px**, визуальный размер — по макету: маленькие кнопки (36–40 px в плеере, сегменты SD/HD, чипы, кнопка очистки поиска) добирают зону через `padding` или `::before`.
- `aria-current="page"` у активного раздела, `aria-pressed` у переключателей качества, `aria-expanded` у «Читать полностью».
- Плеер управляется с клавиатуры (§5.5).
- **Поля ввода — `font-size` ≥ 16 px.** iOS Safari приближает страницу при фокусе на поле с меньшим шрифтом, и контент «уезжает» за рамки экрана. Отключать зум через `viewport` (`maximum-scale`, `user-scalable=no`) нельзя — это ломает доступность. Правило действует для любых `input`/`textarea`/`select` (кроме `range`, `checkbox`, `radio`); страховка — в `styles/global.css`.
- `lang="ru"`.

## 10. Сборка и деплой

- Деплой в **GitHub Pages через GitHub Actions** (Settings → Pages → Source: GitHub Actions; если прав включить из CI не хватает — попросить владельца репозитория).
- Workflow `.github/workflows/deploy.yml`: на `push` в `main` и вручную (`workflow_dispatch`).
  1. `npm ci` → `npm run lint` → `npm run typecheck` → `npm test -- --run` → `npm run build`.
  2. Прямые ссылки на SPA: скопировать `dist/index.html` в `dist/anime.html`, `series.html`, `movies.html`, `search.html` (Pages отдаёт `/anyview/anime` из `anime.html` с кодом 200) и в `dist/404.html` (для `/title/*` — открывается приложение, но с кодом 404; для MVP приемлемо). Работу `x.html` проверить на первом деплое.
  3. `actions/upload-pages-artifact` → `actions/deploy-pages` (permissions `pages: write`, `id-token: write`).
- Vite `base` = `VITE_BASE` (по умолчанию `/anyview/`). Роутер получает `basename` из `import.meta.env.BASE_URL`.
- `public/manifest.webmanifest` Vite не переписывает: `start_url` и `scope` — `"./"`, пути иконок — относительные.
- В README репозитория: адрес сайта, `npm run dev`, переменные окружения.

## Приложение. Название

Рабочее название — **anyview** (оно и в макетах). Оно нейтрально к типу контента и не завязано на аниме, это плюс для будущих сериалов и фильмов. Альтернативы, если захочется другое (доступность доменов и товарных знаков не проверял):

- **seans** — от «сеанс», коротко и по-русски понятно;
- **kadr** — «кадр», легко запомнить;
- **watchly** — международное, лёгкое;
- **oko** — «око», короткое, хорошо смотрится в логотипе.
