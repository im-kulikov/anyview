# Синхронизация между устройствами

Прогресс просмотра, «Продолжить просмотр» и избранное совпадают на телефоне и компьютере после входа через Google. Своего сервера нет: данные лежат в Firebase Firestore, вход — Firebase Auth. Решения: [ADR-27](adr/README.md) (слияние), [ADR-28](adr/README.md) (провайдер). Экран — SPEC §5.8.

## Что включено в консолях (сделал заказчик)

- Firebase проект `any-view-53b9e`: Authentication → вход Google; Firestore (production-режим) с правилами из `firestore.rules`.
- Домен `im-kulikov.github.io` в Authentication → Settings → Authorized domains и в Google Cloud → Credentials → OAuth 2.0 Web Client → Authorized JavaScript origins (`https://im-kulikov.github.io`).
- Analytics не подключён (`measurementId` не используется).
- Конфигурация сборки — `.env.production` (публичные значения: веб-ключ Firebase и Client ID видны любому посетителю; доступ к данным защищают правила). Сервисные ключи не нужны и в репозиторий не кладутся.

**Правила и удаление.** Опубликованные правила содержат один `allow write` с проверкой `request.resource.data`. При удалении документа `request.resource` равен `null`, проверка даёт ошибку, и удаление отклоняется. Код это учитывает (при отказе перезаписывает документ пустым состоянием), но лучше опубликовать `firestore.rules` из репозитория: в нём `delete` разрешён отдельно, остальное совпадает. Консоль Firebase → Firestore → Rules → вставить → Publish.

Для локальной проверки (`npm run dev`) значения нужно положить в `.env.local`, а в OAuth-клиент добавить `http://localhost:5173` в Authorized JavaScript origins.

## Модель данных

Один документ `users/{uid}` = `{ schema: 1, updatedAt: serverTimestamp(), data: "<JSON>" }`. Читать и писать может только владелец. `data` — строка JSON (< 200 000 символов по правилам; код держит ≤ 190 000 байт UTF-8 и при превышении отбрасывает самые старые записи прогресса и истории, затем «надгробия» удалений и избранное; локальные данные не режутся):

```
{ v: 1, progress: {episodeId: {titleId, position, duration, updatedAt}},
  history: [{title: TitleSummary, episodeId, episodeName, still?, position, duration, updatedAt}],
  favorites: TitleSummary[], favMeta: {titleId: {at, del?}} }
```

Не синхронизируются настройки плеера и недавние поисковые запросы. Видео и поисковые запросы в облако не попадают.

## Как работает слияние

Подробности — ADR-27. Коротко: прогресс по серии — побеждает более свежая запись; история — одна запись на тайтл, более свежая, а запись, которую обогнал досмотренный (≥ 90 %) прогресс, отбрасывается; избранное — объединение с метками времени и «надгробиями», удалённое не воскресает, при равных метках удаление сильнее. Слияние чистое, коммутативное и идемпотентное. Чтение, слияние и запись идут одной транзакцией; если другое устройство успело записать, Firestore повторяет транзакцию, и слияние считается заново. Локальные данные облаком вслепую не затираются: после обмена слитое ещё раз сливается с актуальным локальным.

Когда синхронизируем: вход (первое слияние локального с облачным без потери данных обеих сторон); старт приложения (через 2 с) у уже входившего; возврат на вкладку, но не чаще раза в 60 с; через 5 с после изменения данных; при скрытии вкладки и `pagehide` — best-effort; сетевые ошибки — повтор через 5, 10, 20 … с (до 6 раз, потолок 5 мин), затем кнопка «Повторить»; офлайн ничего не делаем, по событию `online` синхронизируем.

## Ограничения и вопросы

- **Safari (ITP)**: данные сайта (включая `localStorage` и IndexedDB, то есть и сессию Firebase) стираются после 7 дней без посещений, если сайт не добавлен на экран «Домой». Прогресс из облака вернётся после повторного входа, но потеряется то, что не успело уйти в облако. Это ограничение браузера.
- **Часы устройств** считаются примерно верными (метки — `Date.now()`); расхождение в дни может отдать победу не тому устройству.
- **Доступность Google и Firebase из РФ не проверена**: при недоступности вход не сработает, сайт продолжит работать без синхронизации.
- **152-ФЗ**: на странице сказано, что хранится (идентификаторы, позиции, названия избранного) и что аккаунт Google обрабатывают Google и Firebase. Нужна ли какая-либо дополнительная обработка (хранение за пределами РФ, согласие, политика) — вопрос к заказчику, юридических выводов здесь нет.
- **Квоты Spark** (бесплатный тариф Firestore): порядка 50 000 чтений и 20 000 записей в сутки на проект. На пользователя приходится одна транзакция (чтение + запись) на синхронизацию; запись пропускается, если облако уже совпадает. Для личного использования с запасом; при росте аудитории следить за расходом в консоли.
- Файл `anyview:sync` в `localStorage` — только флаг «входил на этом устройстве». Токены не хранятся нигде, кроме собственного хранилища Firebase Auth (IndexedDB).

## Чек-лист ручной проверки (два устройства, например телефон и компьютер)

Реальный вход и запись в Firestore из среды разработки проверить нельзя, поэтому это нужно сделать вручную.

1. **Вход.** Компьютер: `/sync` → «Включить синхронизацию» → кнопка Google → выбрать аккаунт. Ожидается «Вы вошли как …» и «Последняя синхронизация: время». В консоли Firebase → Firestore появился документ `users/<uid>` с полями `schema`, `updatedAt`, `data`.
2. **Первое слияние.** Телефон: до входа посмотреть пару серий и добавить в избранное другой тайтл. Войти тем же аккаунтом. Ожидается: на телефоне есть и прогресс/избранное с компьютера, и свои; на компьютере после возврата на вкладку (или «Синхронизировать сейчас») — тоже.
3. **Прогресс телефон → компьютер.** На телефоне посмотреть серию до середины, подождать ≈ 10 с или свернуть вкладку. На компьютере вернуться на вкладку или нажать «Синхронизировать сейчас»: «Продолжить просмотр» показывает серию, плеер продолжает с той же позиции.
4. **Досмотрено.** На телефоне досмотреть серию до конца (≥ 90 %): запись переходит на следующую серию. На компьютере после синхронизации — то же, старая запись не воскресает.
5. **Избранное с удалением.** Добавить тайтл на компьютере, синхронизировать, увидеть на телефоне. Удалить на телефоне, синхронизировать. На компьютере после синхронизации тайтла в избранном нет и он не возвращается.
6. **Выход.** «Выйти»: статус сменился на «Включить синхронизацию», локальные данные остались; изменения больше не уходят в облако.
7. **Удаление данных.** Войти снова, «Удалить данные из облака» → подтвердить. Документ `users/<uid>` исчез из консоли (или содержит пустое состояние, если правила не обновлены), на этом устройстве выполнен выход, локальные данные на месте.
8. **Офлайн.** Войти, включить авиарежим, посмотреть серию, затем вернуть сеть: через несколько секунд данные уходят сами (без ошибки на экране). Для проверки ошибки: заблокировать сеть при открытой странице и нажать «Синхронизировать сейчас» — «Нет связи с облаком…», затем повтор.
9. **Safari и 7 дней.** Safari на iPhone/Mac: войти, не открывать сайт 7+ дней (или стереть данные сайта в настройках). После открытия: сессия потеряна, локальные данные пусты; снова войти — прогресс вернулся из облака.
10. **Консоль браузера.** На `/sync` и после входа нет ошибок и нарушений CSP (`Refused to …`).
11. **iPhone.** Кнопка Google нажимается с первого касания, всплывающее окно не блокируется, страница не масштабируется.
