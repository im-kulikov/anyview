Цель SPEC §8: ≥ 90, допустимо ≥ 80. **Цель не достигнута, допустимый минимум тоже** (холодный старт). Замеры в песочнице идут через прокси, поэтому абсолютные значения не совпадают с задеплоенным сайтом; сравнивать можно только строки между собой. Разброс между прогонами ±1–2 пункта, LCP ±0.5 с.

Что выяснено (эксперименты на prod-сборке, по 3–4 прогона):
- LCP определяет цепочка «ответ API (106 КБ без сжатия, ≈ 1.3 с) → обложка 167 КБ с чужого хоста». Симулятор считает полосу общей: пока грузится первая обложка, параллельно стартуют остальные картинки экрана и конкурируют за 1.6 Мбит/с. Заметно выросший LCP после #24 (приоритет трёх первых обложек: 5.9 → 7.3 с на `/` при том же балле) согласуется с этим.
- Не помогают: внешний шрифт убран совсем (74–76), страница ленты 12 вместо 30 (LCP 5.4–6.2 с), отложенная загрузка остальных обложек без изменения цепочки API (75–78).
- Вшитый в сборку снимок ленты + `preload` первой обложки + отложенные остальные обложки дали 79–83, то есть потолок около минимума 80 и только ценой устаревшей ленты у всех новых посетителей и cron-деплоев (отклонено, ADR-21).
- Сделано и измеримо только для повторных визитов: снимок ленты в `localStorage` (экран рисуется без ожидания API; проверено в браузере при заблокированном `/last`).
- Что реально сдвинет холодный старт: прокси или сервер со сжатием ответа и уменьшением обложек (фаза 2), либо правка `Cover` (UI): не запускать остальные обложки, пока не отрисована первая.
- Стартовый JS 126–127 КБ gzip при бюджете 150, CI проверяет.

Повторный замер на задеплоенном сайте после этих PR нужен: песочница не заменяет реальную сеть.

## Отступления и допущения реализации

- Логотип: компонент `Logo` рисует inline-SVG; файлы `public/brand/logo-*.svg` в коде не используются. `logo-horizontal.svg` содержит живой текст (шрифт Exo 2), а не кривые.
- `icon-maskable-512.png`: знак занимает центральные ≈ 50 % вместо 80 %.
- `og:image` — абсолютный адрес из `VITE_SITE_URL` (по умолчанию `https://im-kulikov.github.io` + `VITE_BASE`); при смене домена задать переменную. Превью ссылок на `/title/*` всё равно не получит карточку (404.html).
- Поиск без результатов: API отдаёт 404 без CORS, в консоли остаётся сетевая ошибка (SPEC M6 «нет ошибок в консоли» с этим исключением). См. API_CONTRACT §5.1.
- Тексты десктопного баннера взяты из макета.
- Кэш адаптера (`rawCache`, `playlists`) живёт 5 мин (TTL) и ограничен 500 записями; свежесть дальше решает TanStack Query (API_CONTRACT §5.3).
- Схема `localStorage` версионируется (`anyview:schema`, сейчас 2: метки избранного для синхронизации, SPEC §7, ADR-26, ADR-27).
- Выбор источника по озвучке и атомарность progress/history, обновление снимков избранного, перебор баз для поиска, новые `kind` ошибок, SHA-пины экшенов: не делались, причины в ADR-17, ADR-23 и в PR #26.
- Компоненты `TitleCard`, `Player` обращаются к `provider` напрямую, минуя `queryOptions`-фабрики из `api/hooks.ts` (зона UI/плеера).

## Известные ограничения

- iPhone: серию из нативного полноэкранного режима переключить нельзя (SPEC §5.5).
- Запасная база API включается при сетевых ошибках, таймауте (10 с), 5xx и нечитаемом теле; 4xx — ответ по существу, базу не меняют. Для поиска базы не перебираются.
- Тайтл по прямой ссылке отдаётся GitHub Pages как `404.html` (код 404, приложение открывается). Предпросмотр ссылок в мессенджерах не получит карточку.
- Нет `LICENSE`: лицензия не выбрана.

## Не проверено

- Реальные iPhone, Android, Firefox, Safari: запуск видео с первого нажатия, клавиатура поиска без зума, нижняя панель над «полосой домой». Исключение: фиксация ограничения полноэкранного режима на iPhone (iOS 18.7, Safari 27, 09.10.2026).
- Запуск, когда источники серии не успели загрузиться (SPEC §5.5): работает только если элемент `<video>` уже «разблокирован».
- Доступ к API и видео из РФ.
- Сверка экранов с PNG-макетами: каталога `docs/design/screens/` в репозитории нет, сверка шла по разметке `.dc.html` и токенам.
