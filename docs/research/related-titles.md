# Исследование: связи тайтлов (сезоны, фильмы, OVA, «похожие») в API animevost

Дата исследования: 09.10.2026. Вход для: адаптера (`related`, [API_CONTRACT.md](../API_CONTRACT.md) §5) и будущего сервера (фаза 2, [RESEARCH.md](../RESEARCH.md)).

## 1. Вопрос и короткий ответ

В animevost продолжения — отдельные тайтлы с отдельными `id`, поля «связанные тайтлы» нет. Пример: `av-2729` «Пощади меня, великий господин!» (ONA, 2021), `av-3138` «…(второй сезон)» (2024), `av-4066` «…(третий сезон)» (2026).

Как найти связи без дополнительных данных:

- **Сезоны определяются по русскому маркеру в скобках** в названии («(второй сезон)»). Он надёжнее номера в оригинальном названии.
- **Кандидатов даёт один `POST /search`** по «голове» названия (часть до первого `:`, ` - `, ` — `, `. `). Фильтровать выдачу нужно по границе слова: поиск API работает по подстроке.
- **Остальное (фильмы, OVA, спэшлы, спин-оффы, ремейки, «Часть N») честно показывать как «похожие»**, а не «сезоны».
- **Поиск по оригинальному названию не окупается**: он нашёл связи, которых не нашёл русский поиск, лишь в 3 из 255 случаев (≈1 %), цена — второй запрос на каждую страницу.

| Что | Сколько |

Запросы шли последовательно с паузой 0.35–0.45 с, лимиты API не опубликованы. Скрипты лежат в [`related/`](related/) (см. §8); сами данные не коммитятся (воспроизводятся скриптами).

## 3. Как устроен заголовок

```
Русское название[ (маркер)][ ОВА|ОВА-N] / Original name [N из M[+]] [OVA N из M] [N серия - дата]
```

Маркеры в русской части (частоты на выборке 1000 тайтлов):

| Маркер | Примеры | Частота |
|---|---|---|
| Сезон словами | «(второй сезон)» 135, «(третий сезон)» 45, «(четвёртый сезон)» 12 (+6 «четвертый»), «(пятый сезон)» 12, «(шестой сезон)» 5, «(седьмой)», «(одиннадцатый)»; «(первый сезон)» 3 | 22 % тайтлов |
| Сезон цифрой | «(2 сезон)», «(2-й сезон)» | редко |
| Фильм | «(фильм)» 11, «(фильм второй)», «(фильм  второй)» с двойным пробелом, «(коллекция фильмов)» | 3 % |
| Спэшл | «(спецвыпуск N)», «(спэшл N)», «(cпэшлы)» — **с латинской `c`** | <1 % |
| OVA | `ОВА`, `ОВА-N`, `OVA-N` как часть названия (не в скобках) | `type` = OVA у 5 % (54 из 1000) |
| Год | «(2021)» у ремейков и пересъёмок | редко |

Поле `type`: «ТВ» 843, OVA 54, «полнометражный фильм» 46, ONA 40, «ТВ-спэшл» 10, «короткометражный фильм» 7. Регистр непостоянен (`Полнометражный фильм`, `полнометражный фильм`).

Подзаголовок через `:`, ` - `, ` — ` или `. ` есть у **17 %** баз (154 из 879): `Власть книжного червя: Приёмная дочь лорда`, `О моём перерождении в слизь. Дневник слизи-попаданца`.

Мусор в строках, который нормализация должна убирать: литеральные обратные слэши перед кавычками (`Queen\'s Blade`, `\"Волшебство Гайдэн\"`), разные `ё`/`е` у сезонов одной франшизы («Индекс Волшебства» / «Индекс волшебства»), регистр.

## 4. Результаты

### 4.1 Русский маркер надёжнее оригинала

У 220 тайтлов есть русский маркер сезона. Из них у 131 в оригинале тоже есть номер (`2nd Season`, `Season 2`, `Part 2`, римская или арабская цифра в конце), и в **130 из 131** номера совпали. Единственное расхождение: «Мастер Муси (третий сезон)» / `Mushishi Zoku Shou 2`.

Обратное неверно: цифра в конце оригинала часто часть названия (`Triage X` → 10, `Brave 10`). **Номер сезона из оригинала брать нельзя.**

### 4.2 Поиск по базовому русскому названию собирает сезоны

Для 117 франшиз с маркерами в ленте: полная непрерывная цепочка нашлась в 113. Остальные случаи:

| Случай | Пример |
|---|---|
| Ремейк/пересъёмка с тем же названием, оба «без маркера» | «Когда плачут цикады» (2006 и 2020), «Рояль в лесу» (сериал и фильм) |
| Первый сезон под другим русским названием | «Записи о магии: Девочка-волшебница Мадока "Волшебство Гайдэн"» (второй и третий сезоны есть, первого под этим названием нет) |
| Разрыв номеров | «Покемон»: сезоны 1 и 11 |

### 4.3 Поиск API — по подстроке

Запрос «Саки» возвращает «Осаки», «Сасаки», «Ханэсаки»; «Небо» — любые названия со словом внутри. Поэтому результат нужно фильтровать по **префиксу по словам** (`название == база` или `начинается с база + пробел`). Совпадения «слово внутри» (`Боруто: Новое поколение Наруто` для запроса `Наруто`) в «похожие» не берём: для однословных запросов это шум.

### 4.4 «Голова» названия — главный способ найти связанное

Из 80 поисков по «голове» 38 дали группы из нескольких тайтлов. Это находки, которых нет при поиске по полному названию:

- `Золотое божество: Финал` — пятый сезон без маркера, рядом «(второй…четвёртый сезон)».
- `О моём перерождении в слизь`: «(второй)» и «(третий сезон)», «Дневник слизи-попаданца», фильмы «Алые узы» и «Слёзы синего моря», OVA «Мечта Колеуса».
- `Реинкарнация безработного: История о приключениях в другом мире`: «(второй)», «(третий сезон)», «Часть 2».
- `Тёмный демон` / `Тёмный демон: Водопад Кэгон в Никко`, `Король шаманов` / `Король шаманов (2021)` / `Король шаманов: Цветы`.

Один запрос по «голове» заодно возвращает и сезоны (ответ — надмножество запроса по полной базе), поэтому достаточно **одного поиска на франшизу**.

### 4.5 Оригинальное название как второй поиск — почти бесполезно

Строгое совпадение по оригиналу дало лишние связи в 3 из 255 запросов: спин-офф `Naruto SD` (Chibi), фильм «Путешествие Кино (фильм второй)» с другим русским названием, «Выдающиеся звери» (русская база с подзаголовком «Финал» — уже закрывается «головой»). Ещё 6 запросов дали только шум подстрок. Вывод: **не делать**; максимум — запасной вариант, когда основной поиск вернул только сам тайтл.

### 4.6 Качество предложенной классификации

Прототип ([`related/lib.py`](related/lib.py), `classify`) прогнан на 336 сохранённых выдачах (за «текущий» взят первый результат; сам он из «похожих» исключён):

| Показатель | Значение |
|---|---|
| Сезонов в группе: 0 / 1 / 2 / 3 / 4+ | 45 / 155 / 85 / 28 / 23 |
| Есть «похожие» | 72 группы (21 %), нет — 264 |
| Максимум результатов в выдаче | 30 (лимит API — 50 — не достигался) |
| Больше 12 «похожих» | «Наруто» (18), «Ван Пис» (24), «Ван Пис: Бегство» (24) |
| Ложные «похожие» в ручной проверке 45 случайных | 0 (всё — фильмы, OVA, спэшлы, спин-оффы, продолжения) |

Те же правила, перенесённые в TypeScript (адаптер), прогнаны на **всех 881 тайтле** из 336 сохранённых выдач (каждый тайтл как «текущий»): сезонов 0 / 1 / 2 / 3 / 4+ = 26 / 157 / 94 / 32 / 27, «похожих» нет у 57,3 % тайтлов (есть у 42,7 %); результаты совпали с прототипом в 880 случаях из 881 (расхождение — год «1998-2014» у Pokémon не парсится в число и влияет на сортировку).

> Две разные цифры не противоречат друг другу: 21 % — доля поисковых запросов, у которых *первый результат* имеет «похожие» (большинство запросов — одиночные тайтлы); 42,7 % — доля *всех тайтлов в выдачах* (в больших франшизах каждый тайтл видит остальных). Для оценки нагрузки на интерфейс важнее вторая. В обсуждении ранее называлась цифра «≈64 % без похожих»: она получена на другой выборке (по три тайтла на запрос, текущий тайтл из «похожих» не исключался) и с этими цифрами не сопоставима.

Случаи, где «похожих» нет, — это тайтлы без продолжений или с продолжениями под другим названием (§6).

## 5. Алгоритм

Определения (нормализация `norm`: нижний регистр, `ё→е`, убрать обратные слэши и пунктуацию, схлопнуть пробелы):

- `ru` — русская часть до ` / ` без хвоста `[…]`.
- `marker` — скобочные маркеры из §3 (сезон, фильм, спецвыпуск/спэшл, `коллекция фильмов`); `full(x) = ru(x)` без этих маркеров.
- `B(x) = norm(full(x))`; `H(x) = norm(голова(full(x)))`, голова — часть до первого `:`, ` - `, ` — `, `. `.
- Запрос: `голова(full(T))`, если её длина ≥ 4 символов, иначе `full(T)`.

Кандидаты — результаты, у которых `H(x) == H(T)` или `B(x)` начинается с `H(T) + " "`.

- **Сезон**: кандидат с `B(x) == B(T)`, `type ∈ {ТВ, ONA}`, без маркеров фильм/спэшл. Номер — маркер сезона; без маркера — 1. Если у двух сезонов один номер — **оба** идут в «похожие».
- **Похожие**: остальные кандидаты, кроме самого `T`. Сортировка: год, затем `id`.

Сезоны показываются при ≥ 2 элементах, «похожие» — при ≥ 1. Кэш — по нормализованному запросу (переходы между сезонами не плодят запросов). Ошибки поиска дают пустой ответ, а не ошибку страницы.

## 6. Ограничения и неочевидные случаи

1. **Разные русские названия у частей одной франшизы** не связываются: «Наруто» и «Боруто: Новое поколение Наруто», «Фейт» с несколькими подназваниями без общей «головы».
2. **Ремейки с одинаковым названием** («Когда плачут цикады» 2006/2020) дают дубль номера → оба в «похожих».
3. **Разрывы в нумерации** (Pokémon: 1 и 11) показывать как есть; «додумывать» пропущенные сезоны нельзя.
4. **«Часть N»** после `:` (`…: Часть 2`) — не сезон, а часть сезона; в «похожих».
5. **Год в скобках** «(2021)» делает базу другой → ремейк не попадает в сезоны (это желательно).
6. **Подстроки в поиске**: любой запрос короче ≈4 символов шумит; фильтр по границе слова обязателен.
7. **Поиск «ничего не найдено»** отвечает HTTP 404 без CORS-заголовка, в браузере это `TypeError` (см. [API_CONTRACT.md](../API_CONTRACT.md) §5.1). Для связей это допустимо: ошибка = «связей нет».
8. **Крупные франшизы** (Наруто, Ван Пис, Покемон): «похожих» десятки; UI показывает первые ~10 с раскрытием.
9. **Латинская `c` в «cпэшлы»** и двойные пробелы в «(фильм  второй)»: регулярные выражения должны это терпеть.
10. **Тип «ТВ» бывает у фильмов** (по отчёту ревью документации, этим исследованием не перепроверено): тип не стоит использовать как единственный признак фильма; русский маркер надёжнее.

## 7. Рекомендации для сервера (фаза 2)

Здесь связи не нужно угадывать по заголовкам на каждый запрос.

1. **Индекс франшиз строить офлайн по всему каталогу** (3603 тайтла) теми же правилами (§5), а результат хранить: `franchiseId`, `seasonNumber`, `relation` (`season | movie | ova | special | spinoff | remake | part`). Тогда `GET /titles/{id}/related` — чтение, а не поиск, и нет ограничения в 50 результатов и подстрок.
2. **Сохранить правила как запасной вариант** и тесты на реальных строках (корпус из §3–§4 готов).
3. **Внешние графы связей** (Shikimori `related`, AniList `relations`, Jikan relations; см. сопоставление идентификаторов в [RESEARCH.md](../RESEARCH.md)) дадут то, чего нет в заголовках: пререквел/сиквел/спин-офф, франшизы с разными названиями (Наруто/Боруто). **В этом исследовании не проверялись**: нужно проверить покрытие сопоставления animevost ↔ MAL/Shikimori и качество связей.
4. **Контракт**: `RelatedTitles { seasons: SeasonLink[]; similar: TitleSummary[] }` уже подходит; серверу стоит добавить тип связи для «похожих» (фильм, OVA, спэшл…), клиент может подписать его.
5. **Метрики качества**: доля тайтлов в франшизах ≥ 2 сезонов, доля дублей номеров, доля франшиз без первого сезона, ручная выборка «похожих» (в этом исследовании ложных 0 из 45).
6. **Сопровождение**: при добавлении тайтла перестраивать только его франшизу (ключ — нормализованная «голова»).

## 8. Что не исследовано

- Выборка — 28 % каталога (случайные страницы ленты). Редкие форматы (ONA-сериалы с «частями», «ТВ-N» в старых названиях, составные названия через «/» внутри русской части) могли не попасть.
- Не проверялись франшизы с >50 результатами поиска (лимит API), поведение при частых запросах (лимиты не опубликованы), регистр и язык нестандартных запросов (латиница, цифры).
- Нет ручной оценки полноты: сколько реальных продолжений алгоритм не нашёл (по определению нужен справочник связей, §7 п.3).
- Внешние источники связей (Shikimori/AniList/Jikan) не запрашивались.

## 9. Воспроизведение

Скрипты в [`related/`](related/) (Python 3, без зависимостей); результаты скриптов пишутся в `data/` (в `.gitignore`).

```bash
cd docs/research/related && mkdir -p data && cd data
PYTHONPATH=.. python3 ../fetch_feed.py      # 1000 тайтлов из ленты → feed.json
PYTHONPATH=.. python3 ../search_bases.py    # поиски по русской базе → searches.json
PYTHONPATH=.. python3 ../search_head.py     # поиски по «голове» → searches_head.json
PYTHONPATH=.. python3 ../search_orig2.py    # поиски по оригиналу → searches_orig2.json
PYTHONPATH=.. python3 ../analyze.py         # основные цифры этого документа
```

Запросы идут к `https://api.animetop.info/v1` последовательно с паузами; не увеличивайте частоту. Выборка ленты случайная (`random.seed`), но каталог меняется, цифры могут чуть отличаться.
